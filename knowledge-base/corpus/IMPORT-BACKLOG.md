```bash
# 3) 通过后正式写入并校验
python app/fetch_corpus.py ...（同参数，去掉 --dry-run）

```

## 三、入库验收（四项全过才认）

1. **双源逐条一致**：条数相同、条号从第一条连续、每条 NFKC 归一化后完全相同（`fetch_corpus.py` 自动判，不一致直接退出码 2）。
2. **条号连续**：断号即失败，防止页面分页/折叠导致漏条。
3. **manifest 双源登记**：`sources` ≥2、`article_count` 与实际一致、`status` 属四态。
4. **`import_corpus.py` 通过**：UTF-8、文号唯一、条数相符、条文非空。

## 四、已知坑位

| 坑 | 表现 | 处置 |
|---|---|---|
| 页面尾部噪声 | 页脚版权/导航被并入末条，相似度骤降 | 已内置 `PAGE_NOISE` 过滤 + 末条按「施行」句截断 |
| 章节标题 | 「第六章 附则」被并入上一条 | 已内置 `CHAPTER_HEAD` 跳过 |
| 全角/半角符号 | 「＋」vs「+」造成伪差异 | 比对用 `NFKC` 归一化（只影响比对，不改写正文） |
| 条文内引用 | 「增值税法第三条所称…」被误当新条 | 只认段首「第X条」，正文引用不触发 |
| 繁体镜像 | `big5.www.gov.cn`、地方局繁体版 | 只取简体页；繁简混用会导致比对失败 |
| 同一网站两栏目 | 看似双源、实为同一发布方 | 需为不同发布主体（如 gov.cn + 税务总局政策法规库） |
