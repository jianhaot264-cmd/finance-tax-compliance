## 二、单部导入操作（可复制）

```bash
# 1) 找双源：优先 gov.cn 政策文件库 + fgk.chinatax.gov.cn 政策法规库
#    同一部法规必须有 2 个可抓取的官方页，不接受"同站两个栏目"
# 2) 试运行，先看双源是否逐条一致（不落盘）
python app/fetch_corpus.py --law "中华人民共和国印花税法" --level 法律 \
  --status 现行有效 --effective-date 2022-07-01 \
  --url-a <gov.cn 原文页> --url-b <fgk 原文页> \
  --out stamp-duty-law-2021.md --expect <官方条数> --dry-run
# 3) 通过后正式写入并校验
python app/fetch_corpus.py ...（同参数，去掉 --dry-run）
python app/import_corpus.py
```

## 三、入库验收（四项全过才认）

1. **双源逐条一致**：条数相同、条号从第一条连续、每条 NFKC 归一化后完全相同（`fetch_corpus.py` 自动判，不一致直接退出码 2）。
2. **条号连续**：断号即失败，防止页面分页/折叠导致漏条。
3. **manifest 双源登记**：`sources` ≥2、`article_count` 与实际一致、`status` 属四态。
4. **`import_corpus.py` 通过**：UTF-8、文号唯一、条数相符、条文非空。

## 四、已知坑位

| 坑 | 表现 | 处置 |
|---|---|---|
| 页面尾部噪声 | 页脚版权/导航被并入末条，相似度骤降 | 已内置 `PAGE_NOISE` 过滤 + 末条按「施行」句截断 |
| 章节标题 | 「第六章 附则」被并入上一条 | 已内置 `CHAPTER_HEAD` 跳过 |
| 全角/半角符号 | 「＋」vs「+」造成伪差异 | 比对用 `NFKC` 归一化（只影响比对，不改写正文） |
| 条文内引用 | 「增值税法第三条所称…」被误当新条 | 只认段首「第X条」，正文引用不触发 |
| 繁体镜像 | `big5.www.gov.cn`、地方局繁体版 | 只取简体页；繁简混用会导致比对失败 |
| 同一网站两栏目 | 看似双源、实为同一发布方 | 需为不同发布主体（如 gov.cn + 税务总局政策法规库） |

## 五、批量导入（推荐）：补齐 URL 清单后一键跑完

1. 按 §六 检索词表，逐部用 WebSearch 找**两个不同发布主体**的官方原文页（必须简体）：
   - 源 A 建议 `www.gov.cn`（中国政府网政策文件库 / 要闻）；
   - 源 B 建议 `fgk.chinatax.gov.cn`（国家税务总局政策法规库）；
   - 不用 `big5.` 繁体镜像；不接受同一站点两个栏目充当双源。
2. 把结果写入 `knowledge-base/corpus/batch-sources.json`，每部必填
   `law / out / expect / url_a / url_b`（字段说明见 `app/batch_import_corpus.py` 文件头）。
   `expect` 用官方公布的章条数，不预估。
3. 先 `python app/batch_import_corpus.py --dry-run` 看双源比对；
   通过后 `python app/batch_import_corpus.py` 正式写入并统一跑 `import_corpus.py`。
   逐部结果写到 `reports/corpus-batch-report.json`，任一失败不阻断其余条目，便于分批补齐。

> 已验证可复用样板：增值税法（`vat-law-2024.md` / 38 条）、增值税法实施条例（`vat-regulation-2025.md` / 54 条），
> 双源分别取自 `www.gov.cn` 与 `fgk.chinatax.gov.cn`。
