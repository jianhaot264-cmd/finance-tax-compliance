## 2. P0 · 启动器与日志健壮性

**`start-qa.bat` v2**（旧版备份 `backups/start-qa-v1-2026-11-10.bat`，桌面快捷方式路径不变）：

- 用 `GET /api/health` 真实健康检查替代「仅看端口 LISTENING」；
- 端口被占用但不是本服务时，轮询 10 秒后明确报错，**不盲目启动、不打开浏览器**；
- 启动后轮询健康检查最多 20 秒，就绪才打开浏览器；失败时打印日志末尾并给出路径；
- `TAXQA_NO_BROWSER=1` 环境变量支持无声自检（自动化/巡检用）；
- `chcp 65001` + UTF-8 CRLF，中文提示在原生 cmd 窗口正常显示。

**`app/server.py`**：新增 `_Tee` 把 stdout/stderr 同步写入 `app/logs/server.log`（>1MB 轮转为 `.1`，启动行含时间戳/PID/端口），端口占用时友好报错并以退出码 2 结束。`server.py` 原有 3 处 `print` 均不含用户问题，日志落盘无隐私风险；`*.log` 与 `app/logs/` 已在 `.gitignore` 排除。

**实测**：以无浏览器模式调用 → 端口空闲判定 → 拉起 → 健康检查通过；二次调用走 `ready` 分支（单实例保护生效，全程仅 1 个 python 进程）。日志实际写出 `===== server start 2026-11-10 14:01:12 | pid=21948 | port=8777 =====`。**服务现为独立进程，不再随会话任务回收**——这是此前反复出现「服务被回收」通知的根治。

> 剩余不确定性：启动器输出若经 PowerShell 等工具捕获，会因 UTF-16/UTF-8 双重编码出现渲染噪声（实测真实输出仅 4 行有效内容）；原生 cmd 窗口不受影响。
