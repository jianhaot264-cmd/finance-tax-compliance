## 0. 一句话原则

**放宽的是「信息来源」，不是「证据标准」**：允许 Agent 在触发条件成立时自主向官方渠道核验硬事实，并用可验证信息组织更完整的回复；任何进入答案的事实仍须双源交叉、逐字核对、可溯源、挂四要素，且必须原样通过 trust 四层闸门。知识库仍是**默认结论源**，外部检索只做「更新 / 补充 / 冲突提示」，不改写知识库、不扩写未覆盖领域的结论。

### 放宽与不放宽对照（本次调整的精确边界）

| 现有条款（过度保守处） | 调整为 | 性质 |
|---|---|---|
| 第 1 条「**只依据**对话中给定的知识库上下文回答」 | 改为「以知识库上下文为默认结论源；触发条件成立时可补充经官方渠道核验的硬事实，并逐条标注」 | 放宽 |
| 第 2 条「上下文未覆盖或置信度不足时**明确回答知识库暂无收录**」 | 改为「先按第 1 节判定是否值得一次官方核验；核验成功则给有依据的补充结论，核验失败或仍无覆盖才回落到『知识库暂无收录 / 无法确认』」 | 放宽 |
| 第 7 条「引用须**来自本轮上下文**」 | 改为「知识库引用来自本轮上下文；外部引用须带 `[外部核验·双源]` 标记 + 来源名称 + 官方链接 + 核验时间，并与知识库引用分区展示」 | 放宽 |
| 第 3/4/5/6/8/9/10/11/12/13/14 条、三重弃答、四层 trust、确定性计算不走 LLM、逐字法条判定 SOP、隔离项不作确定结论、角色分诊、免责声明 | **一字不改** | 不放宽 |

## 1. 触发条件（自主检索决策）

Agent 在生成答案前先做一次轻量判定；**任一触发信号成立**才允许发起外部检索，否则直接走现有知识库链路（零额外开销、行为与今天完全一致）。

### 1.1 时效触发（TIME）

- 问句含时效词：`最新 / 现行 / 目前 / 今年 / 刚发布 / 是否延续 / 到期 / 废止 / 修订 / 新规 / 施行 / 生效 / 过渡 / 衔接 / 2026 / 2027 / 之后`。
- 命中知识库条目含状态：`草案阶段`、`修订中`、`已废止`、`汇编·动态`，或带 `expiry_date` 且距当前 ≤ 90 天（`41-expiry-alerts.md` 的 90/60/30 机制）。
- 条目 `verified_at` 距当前 > 30 天（`trust.py` L1 已有 30→180 天衰减口径），且问题依赖该条目的硬指标。
- 现实依据：知识库快照日为 **2026-11-09**，而财政部会计司「政策发布」栏目在此前仍持续更新（实测可见 2026-08-27《会计师事务所职业责任保险实施办法》、2026-08-05《企业会计准则第30号——财务报表列报》财会〔2026〕11 号、2026-06-17 栏目列出的《企业会计准则解释第20号》通知等）。快照日 ≠ 法规静止日，这是时效触发存在的理由。

### 1.2 覆盖触发（COVERAGE）

- `retrieve()` 返回 `abstain=true`，或 Top1 置信度低于 `ABSTAIN_THRESHOLD`（当前 0.45）且无强字面信号。
- 命中条目 tier 为 **B1 / B2**，或字段含 `待核验 / 凭既有知识 / 以官方原文为准`。
- 问题落在 `00-index.md` §5 已明示**未逐一收录**的范围：各税种全部财政部/总局公告、各省市地方配套、具体行业核定征收标准、七地以外协定逐条税率、差额征税逐项目清单。
- 问题涉及 `PENDING-VERIFICATION.md` 的隔离项（P-06b 广东工伤条例/省级非税、P-24 南沙 15%、P-10b、P-23）。

### 1.3 冲突触发（CONFLICT）

- `trust.py` L2 报 `doc_no_conflict`（同名不同文号）或 `status_conflict`（一废一现）。
- 用户在问句中给出一个与知识库不同的说法（「不是已经改成…了吗」「听说取消了」）。
- 疑似「法条原文 ≠ 现行执行口径」（`SYSTEM_PROMPT` 第 5 条已列四处：企税条例 512 号令两次修订、专项附加扣除 7 项、职工教育经费 8%、消费税附表税率）。

### 1.4 明确不触发（NEVER）

1. 精编问答规则精确命中（`mode=rule`，109 条）——直接给既有答案。
2. 确定性计算类（增值税/个税/企税/印花/契税）——强制走 `app/tax_calc/`，**LLM 不参与数值结果**，检索不得介入。
3. 概念定义/辨析/因果/条件类且解释层（25–28 文件）齐全——按第 10 条两层依据作答。
4. 高风险事项（虚开、偷税、骗税、重大补税）——仍强制转介执业税务师/律师，不因检索放宽。
5. `OUT_OF_SCOPE_RE`（火星/公海/虚拟国家等）与 `UNANSWERABLE_PATTERNS`（穷举、无数据精算）——仍弃答。
6. 用户明确要求「只按知识库 / 离线 / 不要联网」。
7. 四要素（事项·主体·场景·地区）缺失且会改变答案——仍按第 14 条先做选项式追问（最多 2 轮），**不得用检索代替澄清**。
8. 运行环境为离线模式或检索适配器未启用。

## 2. 允许自主检索与回复的范围

### 2.1 渠道白名单（继承 `SOURCES-CHANNELS.md` 分级，不新开来源）

| 级别 | 渠道 | 允许用途 |
|---|---|---|
| A | 国家法律法规数据库 `flk.npc.gov.cn`、中国政府网政策文件库 `gov.cn/zhengce`、税务总局政策法规库 `fgk.chinatax.gov.cn`、财政部会计司 `kjs.mof.gov.cn`、财政部法规库 `fgk.mof.gov.cn`、人社部 `mohrss.gov.cn`、海关总署、广东省政府/省人大/省税务局/省人社厅 | **可作结论依据**（须双源交叉） |
| B | 部委政策解读、答记者问、《中国税务年度报告》、中国税务报 | 仅用于理解口径、交叉核对，**不单独作依据** |
| C | 12366 平台问答、各省市热点问答 | 仅作执行口径参考，必须标注「地方口径，须属地确认」 |
| D | 北大法宝、威科、律所/会计师事务所解读 | 仅用于定位文号与比对版本沿革，**不得替代官方原文** |
| E | 自媒体、短视频、未署名公众号、论坛 | 禁用；仅可作为发现线索后回到 A/B 级核实 |

> 2026-11-09 实测可达：`kjs.mof.gov.cn/zt/kjzzss/kuaijizhunzeshishi/`（会计司准则专栏，直接列出 CAS1/4/6/8/9 等全文）、`fgk.chinatax.gov.cn`、`flk.npc.gov.cn`。

### 2.2 检索目标白名单（只补四类硬事实）

只允许核验：① 法规/准则**是否现行有效**；② **文号、公布日、施行日、到期日**；③ **金额门槛、比例、期限、税率、人数**；④ **最新公告或解释的发布与衔接安排**。

**禁止**借检索生成：会计分录与账务处理流程、税务筹划或操作空间建议、个案合规裁定、税额测算、对未收录业务领域的实体结论、任何形式的「大概/通常/业内一般」推断。

### 2.3 回复中可以做什么（三种动作，不得越界）

| 动作 | 允许内容 | 展示要求 |
|---|---|---|
| **更新** | 指出知识库快照之后的新发布/新施行/到期变化 | 与知识库结论并列，写明「知识库快照 2026-11-09」与「外部核验时间」，并提示需回查原文；**不静默改写知识库条目** |
| **补充** | 为知识库未收录但官方可核验的硬指标补充一行依据 | 单列 `[外部核验]` 区块，不与知识库引用混排 |
| **冲突提示** | 并列展示两种口径及各自时点/效力层级 | 明确写「存在版本或口径冲突，需回查原文」，触发 `change_log` / `PENDING-VERIFICATION.md` 记录 |

**结构不变**：仍是「结论先行（1–3 句 + 可操作建议）→ 依据从简（每条一行）→ 风险与合规提示」，第 7 条「禁止大段复述原文、禁止堆砌无关条款」继续生效。外部依据同样**每条一行以内**，不得因检索而扩写成法规综述。

### 2.4 答案边界（硬性）

- 知识库仍是默认结论源：外部信息只能**补充或提示冲突**，不能在无知识库支撑时独立生成实体结论。
- 不得把「检索到某文件」等同于「该问题适用该文件」；适用性仍按主体/地区/业务/有效期四要素判断。
- 不得把「未检索到」表述为「该规定不存在」。
- 不得用外部信息绕过 `provenance_block()` 的溯源四要素（法条编号 / 适用日期 / 地区口径 / 政策快照时间）。
- 高风险转介、免责声明（首页/结果页/README 三处）、不承诺 100% 准确，全部保留。

## 3. 事实核验与不确定信息标注要求

### 3.1 核验 SOP（沿用 `SOURCES-CHANNELS.md` 八步，外部检索必须完整走完）

1. 定文号 → 2. 找官方原文（优先 A 级）→ 3. 看时效（现行/废止/修订中/草案，记**施行日**而非仅公布日）→ 4. 抓硬指标（金额/比例/期限/人数/税率/文号/条号**逐字核对**）→ 5. 查落地（地方配套、属地口径）→ 6. **双源交叉（≥2 个独立官方源一致）** → 7. 标不确定性 → 8. 留痕（来源名称 + 链接 + 核验时间 + 版本日志）。

- 逐字法条引用前仍须走 `24-verified-traps-2026.md` 的「法条原文 vs 现行口径」判定 SOP。
- 官方原文与解读冲突 → 以原文为准；新旧冲突 → 后法优于前法；特别法优于一般法；上位法优于下位法。
- 草案/征求意见稿 → 标 `[草案·未生效]`，**禁止表述为现行规定**。
- 单源结果 → 标 `[外部核验·单源]`，不得作为确定结论或申报依据。

### 3.2 标注体系（答案中必须可见）

| 标记 | 含义 | 使用约束 |
|---|---|---|
| `[知识库·A层]` | 双官方信源、可直接引用 | 默认结论源 |
| `[知识库·B1/B2]` | 单源或含缺口/汇编型 | 引用数字/文号必须附「建议回查官方原文」 |
| `[外部核验·双源]` | ≥2 独立官方源一致 | 可作补充依据，须附来源+链接+核验时间 |
| `[外部核验·单源]` | 仅 1 个官方源 | 仅作线索，不作确定结论 |
| `[时效待确认]` | 快照日后可能有变化、本次未闭环 | 不作申报依据 |
| `[草案·未生效]` / `[已废止]` / `[已到期]` | 状态提示 | 不得作为现行依据 |
| `[属地待确认]` | 地方口径差异 | 提示按参保地/主管税务机关确认 |
| `[知识库未覆盖]` / `[无法确认]` | 兜底 | 见第 4 节 |

每个外部事实必须挂：**来源名称 + 官方链接 + 核验时间 + 适用日期 + 地区口径**；并写明「知识库快照 2026-11-09」。

### 3.3 不确定信息的表述规则

- 只报验证结果 + 剩余不确定性，不承诺 100% 准确。
- 不确定处写「以官方发布原文为准 / 待核验」，**不得用推测补齐**，不得用「一般来说」「通常是」代替依据。
- 任何未溯源的数字/文号/条号，仍由 `trust.py` L3 判 `ungrounded` 并触发 `block`。
- 答案最终必须过 `trust.py` 四层：L1 时效硬闸、L2 权威层级与冲突、L3 幻觉逐数字溯源、L4 信任分 allow/warn/block；`block` 一律不出结论。

## 4. 检索失败与信息冲突的保守兜底

### 4.1 优先级链

`知识库 A 层结论 > 外部双源一致结论 > 知识库 B1/B2 线索 > 明确弃答`

### 4.2 检索失败（含网络不可达、超时、渠道无结果、返回非官方内容、适配器未启用）

1. **立即回落到知识库**，不重试超过 2 次（避免拖延与噪声）。
2. 输出模板：
   > 「按知识库快照（截至 2026-11-09）的结论是：{结论}。本次未能通过官方渠道核验其现行性，法规立改废释频繁，**请以官方发布原文为准**；涉及申报或对外依据前建议咨询 12366 或主管税务机关。」
3. 不得把检索失败当作「该规定不存在 / 已废止」的否定证据；不得因失败而降级为编造补全。
4. 记录 `query_log` 的检索动作与失败原因，供 `update_watch.py` 后续巡检。

### 4.3 信息冲突

| 冲突类型 | 处置 |
|---|---|
| 外部原文 vs 知识库条目 | **不自动改写知识库结论**；并列展示两者 + 时点 + 效力层级，标注「存在版本/口径冲突，需回查原文」，写入 `change_log` 与 `PENDING-VERIFICATION.md`（不静默改库） |
| 官方原文 vs 官方解读 | 以原文为准，解读仅作理解参考 |
| 上位法 vs 下位法 / 后法 vs 前法 / 特别法 vs 一般法 | 按 `00-index.md` §4 优先级 |
| A 级原文 vs 12366 地方口径 | 以 A 级为准，地方口径标 `[属地待确认]` |
| 草案/征求意见稿 vs 现行规定 | 现行规定为准，草案标 `[草案·未生效]`，不得表述为现行 |
| 涉及「已废止 / 已到期 / 修订中」 | 只对知识库结论**加失效提示**，不删除、不改写原条目 |

### 4.4 最终保守兜底

若核验后仍无法形成可依据结论（无双源、来源互相矛盾且无法按优先级裁定、或问题本身超出收录范围），输出：

> 「该问题本次**无法确认**：知识库未收录可支撑的现行依据，官方渠道亦未取得一致的核验结果。可核对的检索路径为：{渠道名称 + 检索方式}。请以官方发布原文为准，或咨询 12366 / 主管税务机关 / 执业税务师。」

### 4.5 兜底时**不得放宽**的硬边界（防止「为了给完整答案」而削弱质量）

- 不降低 `ABSTAIN_THRESHOLD`、不绕过 `OUT_OF_SCOPE_RE` 与 `UNANSWERABLE_PATTERNS`、不跳过引用完整性校验。
- 不跳过意图对齐（第 14 条）、不跳过角色分诊、不跳过高风险转介。
- 不让确定性计算类问题改由 LLM 或外部信息给数值。
- 不把 B2/解释层条目升级为可直接引用的申报依据。
- 不因新增外部证据而省略结论先行、依据从简、风险提示三段结构。

## 5. 质量约束不变清单（逐条确认）

1. 结论先行、依据从简、禁止大段复述法规原文与无关条款堆砌（第 7 条）。
2. 引用完整性：知识库引用必须来自本轮上下文且 id 有效（`rule_reference` 零悬空）。
3. `trust.py` 四层防线与 `block` 硬闸；时效 30→180 天衰减口径不变。
4. 三重弃答：置信度不足、超范围、不可完成意图，仍按原逻辑弃答。
5. 五态时效标注（含「汇编·动态」不得据此判断现行有效），草案不得写成现行。
6. A/B1/B2 三层分级与 B 层回查提示。
7. 逐字法条引用前的 24 文件判定 SOP 与四处已知订正。
8. 隔离项（P-06b / P-24 / P-10b / P-23）不作确定结论、不作申报依据、不默认南沙 15% 延续。
9. 意图对齐四要素与最多 2 轮选项式追问；角色分诊 `route_role()`；高风险强制转介。
10. 确定性计算走 `app/tax_calc/`，LLM 不产出数值结果。
11. 全程简体中文；不承诺 100% 准确；输出不构成税务师/律师专业意见；三处免责声明保留。
12. 188 题 Golden QA、冒烟 19、e2e 73、trust 24 的回归门禁不变。

## 6. 可执行的调整文本与落地门禁

### 6.1 可直接替换 `SYSTEM_PROMPT` 的条款（落地时使用）

- **替换第 1 条**：「以对话中给定的知识库上下文为默认结论源；仅当触发时效/覆盖/冲突信号时，可补充经 A 级官方渠道双源核验的四类硬事实（现行性、文号与施行到期日、门槛比例税率、最新公告衔接），并逐条标注来源、链接与核验时间。禁止编造法规名称、文号、数字门槛与日期。」
