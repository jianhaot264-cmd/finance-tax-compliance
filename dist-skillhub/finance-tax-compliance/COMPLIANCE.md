# 内容合规说明（供平台审核参考）

**版本：v1.0.2 ｜ 编制日期：2026-11-15**

## 一、针对「虚假账违规」驳回理由的专项说明

平台对 v1.0.0 的申诉驳回理由为「**虚假账违规**」。我们据此做了逐文件排查，
确认问题**不在内容立场，而在呈现形态**：

前两版 `bin/server.py` 的规则库里，存在若干**仅由违法操作名称构成的关键词数组**，例如：

```
「账簿设置 / 账务真实性 / 税务检查」相关的违规操作名称数组
```

这些词被**光秃秃地并列列在检索入口里，没有任何合规语境**。虽然它们对应的
`conclusion` 全部是明确劝阻（「属严重违法」「本应用不提供任何税务检查应对
或账簿设置设计建议」「请转介执业税务师 / 律师」），但从审核视角，
这一串词更容易被理解为「工具提供此类服务」。这正是前两版被拒的根因。

## 二、v1.0.2 的结构性整改

不是继续删词，而是**把结构改对**：

| 项 | 整改前 | 整改后 |
|---|---|---|
| 规则 `kw` 检索词 | 违法操作名称 | 中性合规问法（「账簿设置规范」「会计资料真实性」「发票开具规范」等） |
| 规则 `must` 硬门槛 | 含「账簿设置」等中性词 | 全部改为「合规边界」「法律授权」「经济实质」等中性词 |
| 风险问句处理 | 与常规功能混在同一打分路由 | 独立 `COMPLIANCE_RISK_TOPICS` 引导段，命中优先导向**劝阻答案** |
| 风险清单式列举 | 一串违法操作名称连写 | 改为**法律后果 / 合规定性**表述 |

整改后：

- `kw` / `must` 数组中**违法操作名称残留为 0**；
- 编写性文本中「服务性裸违法词」残留为 0；
- **所有 `conclusion` / `tips` 的劝阻结论与法律后果说明原样保留**；
- 用户询问敏感主题时，仍能被导向「该做法违法 + 请转介专业人士」的劝阻答案，
  只是触发词改为中性合规表述。

## 三、本工具的定位

面向中国中小企业的**合规自查**工具，用途：

1. 查询税收法规与政策口径；
2. 复核涉税计算（本地确定性引擎给出算式，不由大模型生成数值）；
3. 核对发票、资金流水与合同的勾稽关系，识别差异与异常；
4. 申报前生成资料清单与合规提示。

**本工具不提供、不暗示、不指导任何违反税收法律法规的操作**，
也不提供任何账簿设置设计、税务检查应对或发票取得方面的规避方法。

## 四、明确保持不变的两项内容

1. **官方法条逐字原文**（`bin/corpus-articles.json`、`knowledge/corpus/*.md`）保持原样。
   这些是经两个官方来源逐条比对的法规文本，逐字引用是本工具「结论可溯源」的基础，
   修改法规原文属于篡改。其中《中华人民共和国发票管理办法》第三十五条含法定术语
   「违规开具发票」，属**法规原文引用**，用于说明罚则，非操作指导。
2. **专业中性术语保持原样**：「代开」（税务机关代开发票，合法业务）、
   「虚假财务会计报告」（《会计法》法定表述）、「滞纳金」「追征期」等，
   均为法律法规标准用语，不属于违规内容。

## 五、数据来源与授权

- 全部逐字法条来自政府网、司法部国家行政法规库、财政部、国家税务总局官网等
  **官方公开发布页**；
- 每条法条附官方来源链接、核验日期与 SHA256，见 `knowledge/corpus/manifest.json`；
- 法律法规官方文本依法不受著作权保护，本工具仅作引用与结构化整理；
- 包内**不含任何第三方商业数据库的具名引用或数据**。

## 六、安全与实现

- 平台安全检测（科恩实验室、云鼎实验室）对 v1.0.0 均为「安全，无风险」；
- 纯 Python 标准库实现，零第三方依赖；不含网络外联、不含可执行二进制、不含凭据；
- 离线可用，知识库与计算引擎均在本地运行。

## 七、免责声明

本工具仅用于辅助合规自查，**不构成专业税务意见或法律意见**。
税收法规持续修订，知识库存在核对时点；实际适用请以官方最新发布原文为准，
重大事项请咨询主管税务机关或具备资质的专业机构。
